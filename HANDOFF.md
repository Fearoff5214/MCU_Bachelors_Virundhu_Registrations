# BV Registration Portal: Setup Guide

Ticketing portal for Bachelors Virundhu events. One Next.js 15 app (App Router) holds the UI and the backend. There is no separate server.

Read in order: **1. Env setup and gitignore, 2. Installation, 3. Configuration, 4. Config guide (reference).**

---

## 1. Env setup and gitignore

### Env files

The app reads secrets from environment variables. Locally they live in a file called `.env.local` in the repo root. In production they are set in the Vercel dashboard.

```bash
cp .env.example .env.local
```

Then fill in every value (how to get each one is in section 4). `.env.example` is the template: it holds placeholder values only and **is** committed. Real values go only in `.env.local`.

`drizzle.config.ts` and the scripts in `scripts/` load `.env` via `dotenv/config`, so `db:migrate`, `db:seed` and `loadtest:oversell` read `.env`, not `.env.local`. Either copy the file (`cp .env.local .env`, also gitignored) or export the variables in your shell. `npm run dev` reads `.env.local` as normal.

### .gitignore

Current `.gitignore` entries and why they matter:

| Entry | Why |
|---|---|
| `.env`, `.env.local` | Real secrets. **Must never be committed.** |
| `node_modules` | Installed packages, recreated by `npm install` |
| `.next` | Build output |
| `*.tsbuildinfo`, `next-env.d.ts` | Generated by TypeScript/Next |
| `.vercel` | Local Vercel project link |

Recommended additions (not yet in the file):

```
.env*.local
.env.production
.DS_Store
npm-debug.log*
```

Never remove the two `.env` lines. If a secret is ever committed, **rotating it is the only fix**: deleting the file or rewriting history does not undo the exposure. Verify with `git ls-files | grep -i env`, which should list only `.env.example`.

## 2. Installation

Requirements: Node.js 20+ (the project was built on Node 26), npm, git, and a Postgres database (Supabase recommended).

```bash
git clone <repo-url>
cd "BV Registration portal"
npm install
npm run db:migrate    # create tables from drizzle/*.sql
npm run db:seed       # optional sample data
npm run dev           # http://localhost:3000
```

Other scripts:

| Command | What it does |
|---|---|
| `npm run build` / `npm start` | Production build and server |
| `npm test` | Unit tests (vitest) |
| `npm run db:generate` | Generate a new migration after editing `src/db/schema.ts` |
| `npm run db:studio` | Browse the database in a web UI |
| `npm run loadtest:oversell` | Hammer the seat inventory to prove tickets never oversell. Run against **staging**, never production. |

Project layout:

| Concern | Tech | Where |
|---|---|---|
| App / API | Next.js 15, React 19, Tailwind 4 | `src/app` |
| Database | Postgres via Drizzle ORM | `src/db/schema.ts`, `drizzle/` |
| Auth | Auth.js v5, Google sign-in | `src/lib/auth.ts` |
| Seat inventory / holds | transactional reserve, confirm, expire | `src/lib/inventory.ts` |
| Checkout | server actions | `src/app/checkout/actions.ts` |
| Tickets | signed QR tokens, PDF | `src/lib/qr.ts`, `src/lib/pdf/ticket.tsx` |
| Entry scanning | staff scanner page and API | `src/app/scan`, `src/app/api/scan`, `src/lib/checkin.ts` |
| Email | Resend, via an outbox table | `src/lib/email/` |
| Background jobs | Vercel Cron, every minute | `vercel.json`, `src/app/api/cron/*` |
| Payments | pluggable provider interface | `src/lib/payments/` |

## 3. Configuration

Do these once per environment (local, staging, production).

### 3.1 Database (Supabase)
1. Create a Supabase project. Pick the region closest to your users (e.g. Mumbai).
2. Copy the **pooled** connection string (Transaction pooler, port 6543) into `DATABASE_URL`.
3. Copy the **direct** connection string (port 5432) into `DATABASE_URL_DIRECT`.
4. Run `npm run db:migrate`.
5. Turn on backups (point-in-time recovery) before going live.

### 3.2 Google sign-in
1. Google Cloud Console > APIs & Services > Credentials > Create OAuth client ID (Web application).
2. Authorized redirect URI: `http://localhost:3000/api/auth/callback/google` for local, and `https://tickets.<yourdomain>/api/auth/callback/google` for production.
3. Put the client ID and secret into `AUTH_GOOGLE_ID` and `AUTH_GOOGLE_SECRET`.
4. Put the admin Google emails into `ADMIN_EMAILS`. They become admins on first sign-in.

### 3.3 Email (Resend)
1. Create a Resend account and an API key (`RESEND_API_KEY`).
2. Verify your sending domain by adding the DNS records Resend shows you.
3. Set `EMAIL_FROM` to an address on that domain.

### 3.4 Deploy to the subdomain (Vercel)
1. Push to GitHub and import the repo in Vercel (Next.js preset).
2. Add all env vars in Vercel > Settings > Environment Variables (Production).
3. Vercel > Domains: add `tickets.<yourdomain>`. At your DNS provider, add the **CNAME** record Vercel shows.
4. Set `APP_URL=https://tickets.<yourdomain>`.
5. Run `npm run db:migrate` once against the production database.
6. Cron: `vercel.json` schedules two jobs every minute: `/api/cron/expire-holds` (releases unpaid seat holds) and `/api/cron/send-emails` (drains the email queue). **Vercel Hobby allows only daily crons**, so this needs the Pro plan, or an external scheduler calling those routes with `Authorization: Bearer $CRON_SECRET`.

### 3.5 Payments (open item)
The gateway is **not chosen yet**. Only the `mock` provider exists, and it is **disabled in production** (`mockPaymentsAllowed()` in `src/lib/payments/mock.ts`). Until a real gateway is added, a public deploy shows events but **cannot sell tickets**. This is deliberate. Never set `ALLOW_MOCK_PAYMENTS=true` on the public site, or anyone can get free tickets.

To add a gateway, implement `PaymentProvider` (`src/lib/payments/types.ts`):
1. `createOrder`: create the order at the gateway. Return `providerOrderId` and a `clientPayload` for the checkout UI.
2. `verifyWebhook`: verify the gateway signature on the raw body. Return `{ providerOrderId, status: "paid" | "failed" }`, or `null` for bad signatures and irrelevant events.
3. Register it in `src/lib/payments/index.ts` and set `PAYMENT_PROVIDER`.
4. Point the gateway's webhook at `https://tickets.<yourdomain>/api/payments/webhook/<providerName>`.
5. Update `src/app/checkout/[orderId]/page.tsx` to open the gateway's checkout from `clientPayload` (it currently renders only the mock button).
6. Optional: implement `refund`.

Money counts as received only when the verified webhook calls `confirmPayment`. Never trust a browser redirect as proof of payment.

## 4. Config guide (reference)

### 4.1 Environment variables

| Var | Required | Where to get it / notes |
|---|---|---|
| `DATABASE_URL` | yes | Supabase pooled string, port 6543. Used by the running app. |
| `DATABASE_URL_DIRECT` | yes | Supabase direct string, port 5432. Used only by `drizzle-kit`. |
| `AUTH_SECRET` | yes | `npx auth secret` |
| `AUTH_GOOGLE_ID` | yes | Google Cloud OAuth client (3.2) |
| `AUTH_GOOGLE_SECRET` | yes | Google Cloud OAuth client (3.2) |
| `ADMIN_EMAILS` | yes | Comma-separated Google emails that become admin on first sign-in |
| `QR_SECRET` | yes | `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`. **Changing it invalidates every issued QR.** |
| `PAYMENT_PROVIDER` | yes | `mock` until a real gateway is added |
| `RESEND_API_KEY` | yes | Resend dashboard |
| `EMAIL_FROM` | yes | Address on a Resend-verified domain |
| `APP_URL` | yes | Public site URL, used in emails |
| `CRON_SECRET` | yes | Any long random string. Vercel sends it as a Bearer token to `/api/cron/*`. |
| `ALLOW_MOCK_PAYMENTS` | no | `true` enables the fake "Pay (test)" button in production. **Staging only.** |

Use different values for local, staging and production. Never share secrets over chat or email; use the hosting dashboard.

### 4.2 Files that configure the app

| File | Controls |
|---|---|
| `.env.example` | Template of required variables |
| `.gitignore` | What git must never track |
| `drizzle.config.ts` | Migration tool: schema path, output folder, DB URL |
| `src/db/schema.ts` | Database tables. Edit, then `npm run db:generate`. |
| `drizzle/` | Generated SQL migrations. Commit them. Never hand-edit applied ones. |
| `vercel.json` | Cron schedules |
| `next.config.ts` | Next.js settings (remote image hosts) |
| `vitest.config.ts` | Test runner |
| `src/lib/payments/index.ts` | Registry of payment providers |

### 4.3 Before going public
- [ ] Gateway implemented and tested end to end in its test mode, including webhook delivery to the real subdomain
- [ ] `PAYMENT_PROVIDER` is the real provider and `ALLOW_MOCK_PAYMENTS` is unset in production
- [ ] `npm run loadtest:oversell` passes on staging
- [ ] Sign in as an admin, create an event, buy a ticket, receive the email, scan the QR at `/scan`
- [ ] Production secrets differ from dev, and `git ls-files | grep -i env` shows only `.env.example`
- [ ] Supabase backups are on
- [ ] `npm test` and `npx tsc --noEmit` pass

### 4.4 Rules for AI-assisted changes (Antigravity etc.)
- Keep stock and payment-state changes inside the transactional functions in `src/lib/inventory.ts`. Don't update seat counts or order status from elsewhere.
- Schema change: edit `src/db/schema.ts`, `npm run db:generate`, review the SQL, commit `drizzle/`, then `npm run db:migrate`.
- Never paste real secrets into an AI tool's chat or commit them.
